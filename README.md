# classroom-seat-optimizer
학생 데이터와 관계 조건을 반영해 자리·짝·모둠을 추천하는 웹 서비스

## 로컬 실행과 검사

`npm install` 후 `.env.example`을 참고하여 `.env.local`을 준비한다.
`npm run dev`로 실행하고, `npm test`로 입력 검증 테스트, `npm run build`로 빌드를 확인한다.
DB 환경변수가 없어도 입력과 배치 계산은 실행된다.

## 계획서에 맞춘 입력 화면

- 학생 수를 적용하여 입력칸을 생성한다. 현재 지원 범위는 1~60명이다.
- 학번은 중복 없는 숫자 문자열, 성적은 1~10 정수, 시력은 고려 대상 여부이다.
- 친구/앙숙 관계는 두 학생의 순서와 무관하다. 자기 자신, 중복, 모순 관계를 검증한다.
- 학생 학번을 수정해도 관계의 대상 학생은 유지한다. 학생 삭제 시 연결된 관계도 제거한다.
- 그룹 수는 학생 수 이하의 양의 정수이다. 개인 자리와 짝 배치 바로 입력 버튼을 제공한다.
- 한 줄에 놓을 그룹 수(가로 열 수)를 1~전체 그룹 수 사이에서 선택한다. ‘정사각형에 가깝게’는 전체 그룹 수의 제곱근을 올림하여 열 수를 정한다. 25명 개인 자리는 가로 5열 × 세로 5줄로 배치할 수 있다.
- 성적은 균등하게/불균등하게(비슷한 성적끼리)/상관없이, 친구는 떨어뜨리기/붙이기/상관없이를 선택한다.
- 시력 반영과 이전 결과 중복 회피 여부를 각각 입력받는다. 앙숙 분리는 별도의 필수 조건이다.
- 저장된 학생 데이터를 사용할지 명시적으로 선택한다. 로그인만으로 입력을 덮어쓰지 않는다.
- 예시 데이터는 별도 버튼으로 넣는다. 입력 데이터는 브라우저 로컬 저장소에 자동 저장하지 않는다.

## 회원가입·로그인·계정별 저장

1. `.env.local`에 실행 중인 Supabase 프로젝트의 URL과 **publishable key**를 설정한다. 비밀 키·service_role 키는 프런트에 넣지 않는다.
2. Supabase SQL Editor에서 `supabase-schema.sql` 전체를 실행한다. 새 DB와 기존 초기 DB 모두 같은 파일을 사용한다. 재실행할 수 있으며 기존 학생·배치 기록을 지우지 않는다. 예전의 두 migration 파일은 이미 이 통합 스키마에 포함되어 있다.
3. Supabase Authentication에서 이메일/비밀번호 가입을 활성화하고 이메일 인증을 유지한다. URL Configuration에 개발 주소 `http://127.0.0.1:5173/`, `http://localhost:5173/`와 나중의 실제 배포 주소를 등록한다. Site URL도 실제 사용할 주소로 설정한다.
4. 일반 사용자에게 인증 메일을 보낼 때는 Supabase의 SMTP 발송 설정·수신자 제한·요청 횟수 제한을 확인한다. UI 검증의 가입 비밀번호는 8자 이상이며, 서버의 비밀번호 정책도 별도로 적용된다.
5. ‘회원가입·로그인’ → ‘회원가입’에서 이메일·비밀번호·확인을 입력한다. 이메일 인증 후 로그인한다. 서버 설정이 자동 인증인 경우에는 가입과 동시에 로그인된다.
6. ‘내 계정에 저장’은 학생·관계·설정과 현재 생성된 결과를 함께 저장한다. 로그인하거나 배치를 계산하는 것만으로 저장 데이터를 덮어쓰지 않는다.
7. 다시 접속한 뒤 로그인 → ‘저장된 학생 데이터 불러오기·수정’ → ‘저장 데이터 불러오기’로 복원한다. 불러온 학번·성적·시력 고려 여부를 직접 수정하고 학생·관계를 추가·삭제한 뒤, 학생 데이터 영역의 ‘수정 내용 저장’으로 반영한다. 수정 및 저장 상태는 같은 영역에 표시한다. 새 입력으로 기존 DB를 덮어쓰려면 확인을 받는다.

비밀번호는 앱의 학생 테이블에 저장하지 않고 Supabase Auth가 관리한다. Supabase는 로그인 유지용 세션 토큰을 브라우저에 보관한다. 학생 입력은 브라우저 영구 저장소에 자동 저장하지 않는다.
로그아웃·계정 전환 시 이전 학생 입력, 결과, 메모리 이력을 지운다. 로그인 전 새로 작성한 입력은 로그인만으로 지우지 않는다.

### 저장과 접근 제한

`account-service.js`가 인증 입력 검증, Supabase 인증 호출, 계정별 RPC 요청, 오류 안내를 담당한다.
`save_classroom`은 학생·관계·설정·선택적 결과를 하나의 DB 트랜잭션으로 저장한다. 검증 또는 DB 작업이 실패하면 전체를 되돌린다. 통신 중 연결이 끊긴 경우에는 커밋 여부를 단정할 수 없으므로 불러오기로 확인한다.
`revision`으로 다른 창의 오래된 저장을 차단한다. 요청의 소유자 ID와 DB의 `auth.uid()`가 일치해야 하며, 테이블에도 RLS를 적용한다. 친구 관계와 배치 결과가 다른 계정의 학생을 참조하는 요청도 차단한다.
비로그인 사용자는 준비 상태만 확인할 수 있고 학생 테이블과 저장 RPC에는 접근할 수 없다. 함수는 모두 `security invoker`, 빈 `search_path`이며 저장·불러오기 실행 권한은 `authenticated`에만 부여한다.

### 검증 범위와 원격 준비 상태

`npm test`는 입력·배치·worker·인증 어댑터 검증과 함께 PGlite의 실제 PostgreSQL에서 통합 SQL을 실행한다. 테스트용 두 사용자와 역할로 RLS, 소유자 위조 차단, 외부 학생 참조 차단, 버전 충돌, 실패 시 전체 되돌림, 스키마 재실행을 확인한다. Supabase Auth 서버 자체를 테스트용 DB로 대체하는 것은 아니다.
2026-10-31 기존 DNS 조회 실패 프로젝트 대신 `fxafqevybfwdmaqtachc` 프로젝트의 URL·공개 키로 연결을 교체하였다. 사용자가 통합 SQL을 실행한 성공 화면을 확인했고, 원격 준비 상태 함수가 `schema_version: 3`을 반환하는 것을 검증하였다. 이메일 가입은 활성화되어 있고 이메일 인증이 필요한 설정이다.
원격 비로그인 요청으로 5개 테이블과 불러오기 함수가 모두 접근 거부(401/42501)되는 것을 확인하였다. 실제 사용자 계정의 이메일 인증·로그인·저장·재접속 복원은 별도 실계정 검증이 남아 있다. Supabase 관리자의 URL Configuration과 메일 발송 설정 확인도 필요하다.

## 배치 처리(Process)

`arrangement.js`가 화면과 독립적인 계산을 담당하며 `arrangement-worker.js`에서 실행한다.
계산 중 입력이 바뀌면 작업을 취소하여 오래된 입력의 결과를 표시하지 않는다.

1. 각 그룹의 인원이 최대 1명만 차이 나도록 그룹별 정원을 정한다.
2. 배치할 수 있는 그룹이 적은 학생부터 앙숙과 같은 그룹을 피하여 배치한다. 되돌아가기 탐색과 빈 그룹의 대칭 제거를 사용한다.
3. 10명 이하에서는 가능한 그룹 편성을 열거한다. 큰 학급에서는 여러 시작 배치와 학생 교환을 사용해 점수를 개선한다. 교환은 앙숙 분리와 정원을 계속 유지한다.
4. 선택된 성적 분포, 친구 관계, 시력 앞자리, 이전 학생 조합 회피 점수에 동일한 비중을 준다. 사용하지 않는 조건이나 대상이 없는 조건은 평가에서 제외한다.
5. 마지막에 학생 누락·중복, 인원 균형, 모든 앙숙 관계를 다시 검증한다. 필수 조건을 어긴 배치는 출력하지 않는다.

성적 균등은 그룹 평균 성적의 분산을 최소화한다. 불균등은 그룹 안 성적 분산의 합을 최소화하여 비슷한 성적끼리 모은다.
성적 반영도는 `100 × (1 - 분산 / 20.25)`이며 0~100 범위이다. 성적 1~10의 최대 분산인 20.25를 기준으로 한다.
친구는 붙이기/떨어뜨리기 조건이 맞는 관계의 비율이다. 앙숙은 별도의 필수 조건이다.

교실 배치도는 선택한 가로 열 수만큼 그룹 블록을 놓고, 그룹 안에는 최대 2개 자리를 놓는다. 마지막 줄은 남은 그룹만 표시한다. 작은 화면에서는 좌우 스크롤로 열 수와 줄 순서를 유지한다.
선택한 열 수는 시력 조건의 점수 계산, 실제 좌석 좌표, 저장 설정에 함께 적용한다. 열 수가 없는 이전 설정은 한 줄 최대 3개 그룹인 기존 방식으로 불러온다.
시력 대상은 그룹 안에서 앞쪽에 놓고, 그룹 순서도 시력을 고려해 정한다. 맨 앞줄의 실제 좌석에 앉은 시력 대상 비율을 표시한다.
앞자리 정원이 모자라면 시력 반영도가 100%보다 작을 수 있다. 그룹 구성은 앞자리 정렬 때문에 해체되지 않는다.

이전 조합 회피는 이전에 같은 그룹이었던 학생 쌍에 감점을 준다. 그룹 번호가 달라도 같은 학생 쌍이면 중복이다.
이번 방문에서 생성한 최근 20개 결과를 메모리에서 비교한다. 새 입력 시작 또는 계정 변경 시 초기화하며, 브라우저 영구 저장소에 학생 데이터를 저장하지 않는다.
로그인 상태에서는 DB의 최근 20개 배치도 읽어 비교한다. DB 조회 실패 시 이번 방문 기록을 사용했다는 안내를 표시한다.
실제 원격 계정의 DB 조회·저장 검증은 위 준비 절차가 끝난 뒤 수행한다.

기본 탐색 한도는 1.8초 또는 160,000회 연산이다. 제한 안에서 발견한 가장 높은 점수의 배치를 반환하며, 항상 전역 최적해를 보장하지는 않는다.
가능한 필수 조건 배치를 찾지 못하면, 탐색을 끝내 불가능함을 확인한 경우와 탐색 한도를 넘긴 경우를 구분한다.
시드 지정이 가능하여 테스트에서 같은 계산을 재현할 수 있다. 화면의 다시 배치하기는 새 시드로 계산한다.
